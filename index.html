The one loop every training notebook repeats

  1. Load data and look at it (shapes, a few samples, class counts).
  2. Scale / encode / reshape so the model can digest it.
  3. Build layers (Sequential or Functional API).
  4. compile — pick loss, optimizer, metric.
  5. fit — epochs, batch size, validation.
  6. evaluate on held-out data, then predict.

Once that loop is in your bones, CNNs, augmentation, and transfer learning are just better versions of steps 2 and 3.

2. How a neural net learns

A neuron does z = w·x + b, then an activation (ReLU, sigmoid, softmax). A layer is many neurons. Weights and bias are the knobs training turns.

  1. Forward: data flows through layers → a prediction.
  2. Loss measures “how wrong” (not always a percent).
  3. Backpropagation sends that error backward so every weight gets a gradient (“nudge me this way”).
  4. The optimizer (usually Adam) takes a step of size learning rate.
  5. Repeat on the next batch. One full pass over train data = one epoch.

Keras hides steps 3–4 inside fit(). compile(loss=..., optimizer=..., metrics=...) only chooses them. A metric (accuracy, Dice) is a score you watch; it does not update weights unless it is also the loss.

Overfitting

Great on train, worse on val/test. Memorized homework, failed the exam. Fix with dropout, augmentation, early stop, more data.

Underfitting

Bad on train and test. Too simple or not trained long enough.

Train / validation / test: train fits weights. Val is the practice exam during training. Test is the real exam once. Never train on test.

3. CNN — Convolutional Neural Network

A CNN is still a neural net. The new idea is convolution: a small kernel (often 3×3) slides over the image. At each stop it multiplies, adds, and writes one number into a feature map.

Why not Flatten + Dense?

Flatten makes a long list. Neighbor pixels are no longer neighbors. A Dense net does not “see” an edge as an edge.

Local connectivity

Each conv neuron looks only at a small neighborhood — how pictures are built.

Weight sharing

The same 3×3 is reused everywhere. “Vertical edge” costs 9 weights, not a new set per pixel.

Feature hierarchy

Early filters: edges. Deeper: parts (a loop of an 8, an eye). You do not draw them; training writes them.

Stride

Jump size. 1 = scan every pixel. 2 = skip; the map shrinks faster.

Padding

valid = no extra border (28→26 with 3×3). same = pad so size stays when stride is 1.

Pooling

Max 2×2 keeps the strongest value in each block. Smaller maps, a little shift-tolerance.

Receptive field

How much of the original photo one deep number can “see.” Grows as you conv and pool.

Lesson 04 has clickable labs for kernel, output size, and pooling. Lesson 03 is the same MNIST digits as an MLP then as a CNN — CNN wins.

Lesson 00 · Foundation

Images are just numbers in a grid

A camera does not give a computer a “shoe” or a “face”. It gives a table of brightness values. Every later notebook is doing arithmetic on that table.

Pixel Shape Tasks Datasets

A pixel

In these practicals, a grayscale pixel is an integer from 0 (black) to 255 (white). The first Fashion-MNIST comment says “RGB 0–255”. That comment is wrong: Fashion-MNIST and MNIST are one channel, not three.

Color (flowers, CIFAR, fundus photos, webcam faces) has three channels: red, green, blue. Same idea, three grids stacked.

Lab · normalize a pixel

Why divide by 255? Neural nets like small numbers. Huge raw pixels (0–255) make early gradients noisy. MNIST uses / 255 → range 0 to 1. MobileNetV2 and ArcFace use a different scale, about −1 to 1. The preprocess must match the model. Mixing them silently ruins accuracy.

Lesson 01 · Deep_Neural_Network (1).ipynb

A neural net before any images

This practical is not computer vision. That is the point. It teaches the Keras verbs on a small table so later notebooks can reuse them on pixels.

From the notebook: 768 people, 8 medical numbers, one yes/no label called Outcome.

What a Dense layer does

A neuron takes inputs, multiplies each by a weight, adds a bias, then applies an activation.

z = w1·x1 + w2·x2 + … + b    then    y = activation(z)

Dense means every neuron in this layer sees every value from the previous layer. Fully connected. Easy to understand. Bad for raw images later, because it ignores that nearby pixels belong together.

Sequential means you stack layers in a line. Data flows left → right. The diabetes model is only Dense layers.

Lab · one neuron

Activations in this notebook

ReLU on hidden layers

max(0, z). If the weighted sum is negative, the neuron stays quiet. If positive, it passes the number through. Default choice for hidden layers in every notebook here.

Sigmoid on the last layer

Squishes one number into a probability between 0 and 1. Perfect for diabetes yes/no. Not for 10 clothing classes — those need softmax (next lesson).

Compile, fit, evaluate

The comment says this is “configuring back-propagation”. Close enough: compile chooses how errors become weight updates.

model.compile(
    loss='binary_crossentropy',  # yes/no probability
    optimizer='adam',            # adaptive step sizes
    metrics=['accuracy']
)
model.fit(X_train, y_train, epochs=100, batch_size=10)
scores = model.evaluate(X_test, y_test)
model.predict(X_test[11:22])     # probabilities, not 0/1
  • Loss is the number training tries to shrink. Binary crossentropy punishes confident wrong yes/no answers.
  • Adam is the optimizer. You do not write the gradient loop yourself.
  • Epoch = one full pass over the training rows. They used 100.
  • Batch size = how many rows per weight update. They used 10. Smaller batches = more updates per epoch, noisier steps.
  • Accuracy = fraction of correct 0/1 guesses (after thresholding 0.5). Their test run was about 71%.

Backprop in plain language

The notebook comment says compile is “configuring back-propagation.” Here is what that means, without calculus:

  1. The net guesses (forward pass).
  2. Loss says how wrong that guess was.
  3. A gradient for each weight: “if I nudge you up, does loss go down?”
  4. Backpropagation is just the chain rule through the layers, so every weight gets that nudge signal — even the first Dense layer.
  5. Adam (the optimizer) actually changes the weights. Learning rate is how big each change is.

You never write that loop. fit() does it. A metric like accuracy is only a report card. Training follows the loss.

Train / test split

train_test_split(..., test_size=0.2) keeps 20% of rows unseen. That is the only honest score. There is no validation set here — later MNIST adds validation_split=0.2 so you can watch overfitting during training.

Mistakes this notebook leaves in

  • Features are not scaled. Glucose is ~0–200, pedigree is ~0–2. Always scale tables in real work (StandardScaler).
  • Zeros in Insulin / SkinThickness are often missing values, not true zeros.
  • No random_state — the split changes every run.
  • Printing loss * 100 looks like a percent. Loss is not a percent.
  • predict returns probabilities. You still choose a threshold (usually 0.5).

Flatten throws the grid away

A 28×28 photo becomes a list of 784 numbers. Neighbor pixels in the picture are no longer neighbors in that list. The model can still work — humans can classify a shuffled-looking vector less easily than a picture, but a Dense net does not “see” edges as edges. Softmax and argmax

The last layer outputs 10 scores. Softmax turns them into 10 probabilities that add to 1. argmax picks the biggest one — that is the predicted class. The notebook does exactly this on test image 8252 (comments wrongly say “1250th”).

Lab · softmax

Why sparse_categorical_crossentropy

Labels are integers 0–9, not one-hot vectors. Sparse categorical crossentropy is the loss that matches integer labels + softmax. If you first call to_categorical (MNIST notebook), you switch to categorical_crossentropy. Mixing those two is a classic silent disaster.

model.compile(
    loss="sparse_categorical_crossentropy",
    optimizer="adam",
    metrics=["accuracy"]
)
model.fit(X_train, y_train, epochs=10)  # batch 32 by default
# their run: train ~91%, test ~88%

That small gap is mild overfitting: the model is a bit better on pictures it already saw.

What you should take from this practical

You can classify images with Flatten + Dense. It works on tiny grayscale icons. It will not be the right tool for flowers, faces, or medical photos. The next notebook proves that by beating an MLP with a CNN on the same kind of 28×28 data.

Lesson 04 · Theory behind the CNN cells

How convolution actually works

The handwritten notebook uses Conv2D and MaxPool without deriving them. This lesson is that derivation, in the same numbers those cells use.

A filter is a tiny shared pattern-detector

A 3×3 kernel (filter) slides over the image. At each stop it multiplies overlapping pixels by its 9 weights and adds them up. That one number goes into a feature map.

Early filters learn edges and textures. Deeper filters learn parts (loops of an 8, petals, an eye). You do not draw the filters. Training writes them.

Two reasons this beats Flatten + Dense:

  • Local connectivity — a neuron only looks at a small neighborhood, which is how images are structured.
  • Weight sharing — the same 3×3 is reused everywhere, so “vertical edge” is detected in every location with the same 9 weights. Far fewer parameters than a Dense layer on 784 pixels.
MLP (Flatten + Dense)CNN
Sees the photo asA bag of 784 numbersA grid; neighbors stay neighbors
ParametersHuge (every pixel to every neuron)Small shared kernels
TranslationA shifted 7 looks like new dataThe same filter still finds the stroke
Your MNIST run~97.5% test~99.1% test

That is the whole “CNN theory”: convolution = sliding shared filters; then pooling shrinks; then maybe Dense at the end for classes. Everything after this lesson (augmentation, transfer, U-Net) still uses this block.

Lab · 5×5 image, 3×3 kernel

Padding and stride

Stride is how many pixels the kernel jumps. Stride 1 = dense scan. Stride 2 = skip every other location, map shrinks faster.

Padding adds extra pixels (usually zeros) around the border so the kernel can sit on edge pixels too. Keras default is valid (no padding). That is why MNIST goes 28 → 26 with a 3×3 filter: 28 − 3 + 1 = 26. same padding keeps 28 → 28 when stride is 1.

Lab · output size

MNIST CNN path, all valid padding, pool stride 2:

28 → conv 26 → pool 13 → conv 11 → pool 5, then 64 maps → 5×5×64 = 1600 numbers into Dense.

Pooling

Max pooling 2×2 with stride 2 keeps the strongest response in each 2×2 block and throws the rest away. Effects: smaller maps (cheaper Dense at the end), a little translation tolerance (“the edge is somewhere in this 2×2”).

Lab · max pool

Many filters = depth

One 3×3 kernel makes one feature map. Conv2D(32, …) is 32 different kernels, so 32 maps stacked as channels. The next conv looks across those 32 channels at once. That is why the second MNIST conv has more parameters: each of 64 new filters sees a 3×3×32 patch.

params = (kernel_h × kernel_w × in_channels × out_channels) + out_channels (bias)

First MNIST conv: (3×3×1×32)+32 = 320. Second: (3×3×32×64)+64 = 18,496.

Receptive field, in one sentence

After two 3×3 convs and two 2×2 pools, each number in the 5×5 map “sees” a much larger patch of the original 28×28 digit. That is how a CNN goes from local edges to a whole handwritten 4.

Lesson 05 · data_augmentation_comparison.ipynb

Teach the model the same object, slightly wrong

CIFAR-10 is 32×32 color photos (airplane, cat, truck, …). The notebook trains the same CNN twice. Only the training transforms change. That isolates what augmentation is worth.

Framework: PyTorch, not Keras. Same ideas: conv blocks, ReLU, pooling, dropout, cross-entropy, Adam-style optimizer.

What augmentation is

You do not invent new labeled photos. You warp the ones you have: flip, crop, jitter color, small rotate. A flipped cat is still a cat. The model sees more variety and memorizes exact pixels less.

Never augment the test (or validation) set if you want an honest score. The notebook’s test loader is normalize-only.

What they applied

TransformWhy it is fair on CIFAR
RandomHorizontalFlipA car facing left is still a car.
RandomCrop(32, padding=4)Classic CIFAR recipe: pad then crop, like a small shift.
ColorJitterLighting changes should not change the class.
Small rotationSlight camera tilt.
Normalize with CIFAR mean/stdNot /255. Dataset-specific centering. Always denormalize before plotting.

Do not blindly flip digits

A horizontal flip of MNIST 2 is still a 2. A 180° rotation can turn 6 into 9. Augmentation must preserve the label. Fashion shirts can flip; medical laterality sometimes cannot.

The CNN (same for both runs)

Three conv blocks (two 3×3 conv+BatchNorm+ReLU, then max pool), then global average pool, Dense 512, Dropout 0.3, 10 logits. Loss is CrossEntropyLoss on integer labels — PyTorch applies log-softmax inside the loss, so the last layer is not softmax.

Optimizer: AdamW, cosine annealing over 30 epochs. That slowly lowers the learning rate. Different stack, same training story as Keras fit.

How to read the experiment

  • The augmented model’s train accuracy rises slower (training is harder).
  • Its test accuracy ends higher.
  • The gap train_acc − test_acc shrinks. That gap is a simple overfitting score.

Keras version of the same idea: the flowers notebook’s ImageDataGenerator (flip, rotation 20°, shift, zoom, shear, brightness) applied to train only.

Lesson 06 · transfer_learning_tf.ipynb

Borrow a brain that already saw a million photos

You have ~4,300 flower photos and five classes. Training a huge CNN from random weights will overfit. ImageNet already taught MobileNetV2 edges, textures, and object parts. You reuse that.

transfer_learning_tfh.ipynb is the same file. It does not use TF Hub. Dataset: Kaggle alxmamaev/flowers-recognition — daisy, dandelion, rose, sunflower, tulip. Split 70 / 15 / 15.

Transfer learning in two phases

Phase 1 · feature extraction

Freeze the MobileNetV2 backbone. Train only a small new head. Fast. Safe. Learning rate ~1e-3.

Phase 2 · fine-tuning

Unfreeze the last 30 backbone layers. Train them + the head with a tiny LR (~1e-5) so you do not erase ImageNet features (catastrophic forgetting).

include_top=False throws away ImageNet’s 1000-class classifier. You keep the visual trunk and attach your 5-class head.

Input 224×224×3
↓ MobileNetV2 ImageNet weights, include_top=False
GlobalAveragePooling2D → BatchNorm → Dense 256 → Dropout 0.3 → Dense 128 → Dropout 0.2
↓
Dense 5, softmax

Global Average Pooling turns a stack of feature maps into one number per channel. No giant Flatten. Fewer parameters, harder to overfit.

The preprocess trap

MobileNetV2 expects preprocess_input, which scales roughly to [−1, 1]. Using /255 from the MNIST notebooks here will look like it “runs” and still be wrong. Val/test generators use preprocess only — no augmentation.

Call the backbone with training=False so BatchNorm keeps its ImageNet running statistics. If those stats update on a small flower set, the features can collapse. Official TensorFlow transfer-learning guidance is exactly this.

Recompile before Phase 2. A fresh Adam at 1e-5 should not carry Phase-1 momentum into the unfrozen layers.

Grad-CAM

After training, you want to know where the model looked. Grad-CAM takes the gradient of the predicted class score with respect to the last convolutional feature map and paints a heatmap. For flowers, the blob should sit on the bloom, not the table. For eyes (next medical lesson), it should sit on lesions, not the black border.

Evaluate like an adult

Accuracy on five fairly even flower classes is OK as a headline. Still plot a confusion matrix and per-class F1. shuffle=False on the test generator so predictions line up with labels.

Their ballpark: after fine-tune, val ~88–92%, test ~88–91%. Far above what a tiny from-scratch CNN would do on 4k photos.

Lesson 08 · siamese_network_tutorial.ipynb

Stop naming people. Learn a distance.

Softmax over 40 identities fails as soon as person 41 walks in. A Siamese net does not output “Alice / Bob”. It outputs how far two face embeddings are. New people only need a reference photo.

AT&T / ORL: 40 people × 10 photos, grayscale .pgm 92×112. Pairs: 20 same + 20 different per person (label 0 = same, 1 = different).

Shared weights

Two input photos go through the same CNN encoder. Same weights. If the towers differed, “distance” would be meaningless. The encoder ends in a 128-D vector, L2-normalized (length 1), so Euclidean distance behaves like an angle on a sphere.

Image A 112×92×1    Image B 112×92×1
↓ same encoder (4 conv blocks → GAP → Dense 128 → L2)
embedding A    embedding B
↓ Euclidean distance
one number d · contrastive loss

Contrastive loss (Hadsell-style)

This notebook uses y = 0 for the same person and y = 1 for different people. Many tutorials flip that. Copy the formula that matches your labels.

L = ½ [ (1−y) d² + y max(0, margin − d)² ]    with margin = 1.0
  • Same pair (y=0): loss is ½ d². Pull embeddings together.
  • Different pair (y=1): if d already > margin, loss is 0. Otherwise push them apart. No need to send strangers to infinity.

Lab · contrastive loss

Verification vs identification vs one-shot

  • Verification: two photos, same person? Threshold on d (they sweep 0–2 on test; slightly optimistic — prefer tuning on val).
  • Identification: one query vs a gallery, nearest embedding wins.
  • One-shot: gallery has one photo per person. Softmax classifiers cannot do this without retraining.

They also plot t-SNE (pretty 2D view of clusters — not a metric) and ROC-AUC on pair distances.

Optimistic splits

Pair-level train/test still lets the same person appear on both sides. For a true one-shot test you hold out subjects, not just pairs. Tiny 400-image sets also memorize easily without augmentation.

Lesson 09 · Face_Recognition_Based_Attendance.ipynb

You often do not train. You engineer a pipeline.

Siamese taught the idea of embeddings. This notebook downloads a stronger pretrained one (ArcFace) and a face detector, then logs names to CSV. Production CV is frequently this: glue, thresholds, and a UI.

Detection is not recognition

  1. Detect — OpenCV Res10 SSD (300×300) finds a box. Confidence default 0.80, min face 80 px, keep the largest face.
  2. Crop — pad 8% so you do not cut ears/chin, resize to 112×112 RGB.
  3. Embed — ArcFace ONNX, preprocess (x − 127.5) / 128, output 512-D, L2-normalize.
  4. Match — cosine distance to enrolled gallery. Accept if distance < 0.40.
  5. Log — one attendance row per person per day.

Enrollment photos live in known_Faces/ with names like 1234_JohnDoe.jpg. Extra underscores in the name will split wrong — the notebook documents that quirk.

Cosine on the unit sphere

After L2-normalization, cosine similarity is just the dot product. Distance = 1 − similarity. Lower threshold = stricter (fewer false accepts, more “unknown”).

Lab · cosine match

Why ONNX

ONNX Runtime runs a trained model without bringing PyTorch or TensorFlow into the attendance app. Layout matters: this ArcFace is NHWC (1, 112, 112, 3). Many face models are NCHW. Wrong layout → garbage embeddings that still look like 512 numbers.

Limits you should say out loud

  • No liveness check — a printed photo can pass.
  • SSD is old; profile, mask, hard light will miss faces.
  • Threshold 0.40 is a default, not calibrated FAR/FRR on your camera.
  • Face embeddings are biometric data. You need consent and a retention policy. This is a class demo, not a workplace system.

The notebook also writes a Streamlit app.py (upload or camera). Same wrapping pattern as the multi-agent extra: notebook → small web app.

Label-mapping landmine

The folder is named Proliferate_DR. The map used Proliferative_DR. Those 295 images were dropped, so grade 4 never trained. Always print value counts after mapping. Add the typo to the dictionary.

Ben Graham preprocessing

Fundus photos come from many cameras: black circular borders, uneven lighting. The 2015 Kaggle DR winner’s trick, used in this file:

  1. Crop black borders (pixels below a gray tolerance).
  2. Resize to the model size (224 here).
  3. Local contrast: addWeighted(img, 4, GaussianBlur(img, σ), -4, 128) — subtract a blur so large lighting goes away and tiny lesions pop.

This is domain knowledge. ImageNet preprocess alone does not fix a poorly lit retina. Match backbone preprocess after this (EfficientNet is not the same as /255).

Grad-CAM matters more here than on flowers: a doctor should see heat on hemorrhages / exudates, not on the circular mask.

U-Net: down, then up, with shortcuts

A classification CNN shrinks the grid until a vector remains. That throws away where. U-Net (Ronneberger, 2015, biomedical) keeps where:

  1. Encoder — conv + pool. “What is this?” Maps get smaller, channels grow.
  2. Bottleneck — the bottom of the U.
  3. Decoder — upsample back to full size so every pixel can get a label.
  4. Skip connections — copy encoder maps across and concatenate them. The decoder sees both deep context and sharp edges.

Sequential cannot do skips. Same Functional API idea as the Siamese net, different graph.

Input 128×128×1
↓ Conv 16, 16 · pool → 64×64
c1 saved for a skip
↓ Conv 32, 32 · pool → 32×32
c2 saved for a skip
↓ Conv 64 (bottleneck)
UpSample · concat c2 · Conv 32
↓
UpSample · concat c1 · Conv 16
↓ Conv2D(1, 1×1, sigmoid)
Per-pixel P(tumor), then threshold 0.5

This is a mini U-Net: two down-levels, 16→32→64 channels, UpSampling2D instead of learned Conv2DTranspose, padding='same' so concat sizes match. The paper U-Net is deeper. The idea is the same.

Dice, not accuracy

Dice = 2 × |true ∩ pred| / (|true| + |pred|)    ·    dice_loss = 1 − Dice

Tumors are tiny. A model that paints every pixel black can be ~99% accurate and still miss the tumor. Dice only scores overlap of the white blob. IoU (intersection over union) is the harsher cousin; this notebook does not log it.

Lab · Dice vs accuracy

def dice_loss(y_true, y_pred):
    smooth = 1.
    y_true_f = tf.reshape(y_true, [-1])
    y_pred_f = tf.reshape(y_pred, [-1])
    intersection = tf.reduce_sum(y_true_f * y_pred_f)
    return 1 - (2. * intersection + smooth) / (
        tf.reduce_sum(y_true_f) + tf.reduce_sum(y_pred_f) + smooth)

model.compile(optimizer="adam", loss=dice_loss, metrics=["accuracy"])
model.fit(X_train, y_train, epochs=20, batch_size=8, validation_split=0.1)

Checklist (print this next to Colab)

  1. Seed, then look: shapes, a few images, class counts.
  2. Fix labels (typos, missing values, ordinal vs nominal).
  3. Split so test never leaked. Stratify if classes are uneven.
  4. Preprocess that matches the backbone. Augment train only.
  5. Start simple: frozen pretrained net, or a small CNN if data is MNIST-like.
  6. Compile the matching loss. Metric that matches the problem (accuracy vs F1 vs kappa vs Dice).
  7. Callbacks: early stop on val, checkpoint best weights.
  8. Fine-tune last layers with a tiny LR if Phase 1 is healthy.
  9. Confusion matrix, per-class scores, a few mistakes, Grad-CAM if you need trust.
  10. Save the model. For apps, consider ONNX. For faces, write down the threshold and the ethics.
