The one loop every training notebook repeats

  1. Load data and look at it (shapes, a few samples, class counts).
  2. Scale / encode / reshape so the model can digest it.
  3. Build layers (Sequential or Functional API).
  4. compile — pick loss, optimizer, metric.
  5. fit — epochs, batch size, validation.
  6. evaluate on held-out data, then predict.

Once that loop is in your bones, CNNs, augmentation, and transfer learning are just better versions of steps 2 and 3.

2. DNN — Deep Neural Network

Yes — the course starts with a DNN, and almost everything later is still a DNN with a different layer type.

A neural network is layers of simple units. Each unit computes a weighted sum, then a curve (the activation). Deep means more than one hidden layer between input and output. Your file Deep_Neural_Network (1).ipynb is that idea with no images: a stack of Dense layers on eight medical numbers.

Input features (table row, or flattened pixels)
↓ hidden layer 1 (ReLU)
new representation — mixes of the inputs
↓ hidden layer 2, 3, … (ReLU)
richer mixes (this is the “deep” part)
↓ output layer
sigmoid (yes/no) or softmax (which class)

DNN is the family name

People say “DNN,” “deep net,” and “MLP” as if they were different products. In this course they nest:

  • Neural net — at least one layer of neurons with learned weights.
  • MLP (multilayer perceptron) — a neural net whose hidden layers are all Dense (every unit sees every previous value). Diabetes, Fashion-MNIST, and MNIST part A are MLPs.
  • DNN — a neural net with several hidden layers. An MLP with depth is a DNN. A CNN with depth is also a DNN. So is U-Net. “Deep” describes how many stages of mixing, not “must be convolution.”

A CNN is a DNN whose hidden layers are mostly convolutions instead of Dense. A Siamese net is two copies of the same DNN with shared weights. U-Net is a DNN with an encoder that shrinks the grid and a decoder that grows it back.

Why you need a nonlinear activation

A Dense layer without an activation is a linear map: output = Wx + b. Stack two of those and you still have one linear map, because W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂). The extra layer bought you nothing new: you can still only draw a hyperplane.

An activation after each hidden layer bends the space. ReLU folds negatives to zero. After that fold, the next linear map can cut the space in a new way. Many folds stacked together can carve complicated regions — “high glucose and high BMI,” or “a loop that looks like an 8.”

Why stack layers at all? (depth vs width)

A famous theorem says a single hidden layer, if you make it wide enough, can approximate many functions. So why go deep?

Depth is a bet that the world is hierarchical. Layer 1 learns cheap local facts. Layer 2 reuses those facts as parts. Layer 3 reuses parts as objects. That reuse is why a deep net can express some functions with far fewer weights than a huge shallow net. Vision is the textbook hierarchy (edges → parts → objects). The diabetes net is a smaller version of the same idea: combinations of combinations.

Width is how many neurons sit in one layer (how many different patterns that stage can hold). Depth is how many stages of recombination you allow. Too little of either: underfitting. Too much: the net can memorize the training set (overfitting). The diabetes notebook’s 12 → 20 → 20 → 22 units is an arbitrary small capacity, not a law of nature.

Feedforward vs other nets

These notebooks are feedforward: information goes input → hidden → output, no loops in time. Recurrent nets (for sequences) and transformers are not in this folder. Residual skip connections (U-Net) are still feedforward: they copy a tensor sideways; they do not cycle.

Inductive bias (what the architecture assumes)

An inductive bias is the assumption baked into the architecture before you see data. Training only searches among functions the architecture can represent.

  • MLP: “Any input can mix with any other.” Fine for a table of eight numbers. Wasteful for a photo, because it does not know that nearby pixels belong together, or that an edge on the left is the same pattern as an edge on the right.
  • CNN: “Patterns are local, and the same pattern can appear anywhere.” That is why CNNs win on images.
  • U-Net: “Where something is matters as much as what it is,” so high-resolution maps must be copied into the decoder.
  • Siamese: “Identity is a distance in a vector space, not a slot in a fixed class list.”

Why ReLU made deep nets practical

Older nets used sigmoid in every layer. Sigmoid saturates (flat near 0 and 1). In the flat region the derivative is almost zero. Multiply many almost-zeros (one per layer) and the gradient at the first layers vanishes — vanishing gradients. Those layers barely learn; depth becomes a liability.

ReLU is linear for positives, derivative 1, so the signal can travel many layers. That is why hidden layers here are ReLU, and only the last layer uses sigmoid or softmax (you want a probability there, not a ReLU that can be 17).

The opposite problem is exploding gradients: products of large derivatives blow up, weights jump, loss becomes NaN. BatchNorm, careful initialization, and clipping are later tools against that. These notebooks mostly dodge it by staying small and using Adam + ReLU.

What the output layer is allowed to mean

The last layer is not “another hidden layer.” It is a claim about the kind of answer you want.

  • One number in (0,1) → sigmoid + binary crossentropy (diabetes, IMDB, each tumor pixel independently).
  • K exclusive classes → softmax + (sparse) categorical crossentropy (clothes, digits, flowers). Softmax forces the K numbers to be probabilities that sum to 1: you cannot be “90% boot and 90% sandal.”
  • A distance between two embeddings → no class head; contrastive loss (Siamese). The theory changed: you are not naming a class, you are arranging a space.

The last layer and the loss are a pair. Mixing them (softmax with binary crossentropy, or sigmoid with 10 exclusive classes) is the most common compile mistake, and it is a theory mistake, not a typing mistake.

3. How learning works (theory)

A DNN is a function with millions of knobs (weights). Training is optimization: pick knobs that make a loss small on the training set, hoping the same knobs work on new data. Nothing in this step is special to images. The diabetes DNN and a CNN use the same story.

Forward pass

An example enters. Each layer transforms it. You get a prediction ŷ. No weights change yet. The network is just a composed function: ŷ = f_L(f_{L−1}(…f₁(x)…)).

Loss (the thing that is actually minimized)

You need a number that is small when ŷ matches y, and large when it does not. That number is the loss. Gradient descent only “sees” the loss, not accuracy.

Cross-entropy (binary or categorical) is negative log-likelihood of the true class under the model’s probabilities. It punishes a confident wrong probability more than a shy wrong one. If the true class is “boot” and you said 0.99 “trouser,” the loss is large. If you said 0.4 “boot,” it is smaller. That is why we output probabilities during training, not just a hard class.

Why not mean squared error for classification? MSE treats “I said 0.6, truth is 1” as a numeric miss. Cross-entropy treats it as “you assigned too little probability to the true class,” which matches the softmax/sigmoid story and usually trains cleaner classifiers. MSE is a natural loss when the target is a real number, not a class.

Dice loss is different again: it cares about overlap of two blobs, not “how many pixels were correct.” Use it when the positive region is tiny. Same principle: the loss must match the meaning of the output.

A metric (accuracy, F1, kappa, Dice coefficient) is a human-readable score. Gradient descent does not follow accuracy unless you make accuracy the loss (almost nobody does — accuracy is not a smooth function of the weights).

Gradient and backpropagation

A gradient of the loss with respect to a weight is: “if I increase this weight a little, does loss go up or down, and how fast?” You move the weight a small step the downhill way. Learning rate is the step size. Too large: loss explodes or jumps over the minimum. Too small: training crawls.

Backpropagation is the chain rule applied layer by layer from the output back to the input. Because ŷ is a composition of layers, the derivative of loss w.r.t. an early weight factors as (how loss depends on the next layer) × (how that layer depends on this one). The last layer’s error is easy. That error is multiplied by each layer’s local derivative to get the previous layer’s error. That is why vanishing gradients hurt: a chain of tiny local derivatives makes the product ~0.

Keras fit() runs this automatically. You still have to choose a loss that means the right thing, or backprop will faithfully minimize the wrong objective.

Adam is an optimizer that keeps a running average of gradients and of their squares, so each weight gets its own effective step size. You can think of it as “smarter SGD.” SGD itself is: take one (or a batch of) example(s), compute the gradient, step. The loss surface of a DNN is not a bowl — it is non-convex, with many saddles. In practice Adam + ReLU + a sensible learning rate finds a useful region; you are not proving a unique minimum.

Why batches

The true gradient would average over the whole training set (slow, RAM-heavy). A mini-batch is a noisy but cheap estimate. Noise can even help escape bad regions. Epoch = how many times the full set was seen. More epochs ≠ always better (overfitting). Batch size is a trade: large batches → smoother, more “true” gradient, often need a larger learning rate; small batches → noisier, more updates per epoch.

Bias–variance in this language

Underfit (high bias): the net is too simple or under-trained; train and test both poor. Overfit (high variance): train looks great, val/test worse; the net memorized quirks. Depth and extra neurons increase capacity (the size of the function class) — easier to overfit. Regularization (dropout, augmentation, weight decay, early stopping) reduces that extra freedom so the hypothesis you pick is simpler in a useful sense.

Validation is the set you watch to decide when to stop and which idea won. Test is used once. If you keep peeking at test while changing the model, it becomes a second validation set and you fool yourself about generalization.

4. CNN theory (in more depth)

A CNN is still a DNN. The change is the kind of hidden layer. Pictures have a grid: nearby pixels belong together, and the same pattern (an edge) can appear anywhere. Dense layers ignore both facts.

The convolution operation

A kernel is a tiny weight matrix, usually 3×3. You place it on the image, multiply overlapping numbers, add them (plus a bias). That sum is one cell of a feature map. Then you slide the kernel by the stride and repeat. Training learns the 9 (or more) numbers; you do not draw “this is an edge detector” by hand, though early filters often look like edges.

Output width (one side), for kernel size k, padding p, stride s:

out = floor( (in + 2p − k) / s ) + 1

valid padding means p = 0, so a 3×3 on 28×28 becomes 26×26. same padding chooses p so that, with stride 1, out = in. Edge pixels would otherwise be used less often than the center; padding also lets the kernel sit on the border.

Two theoretical reasons CNNs win on images

Sparse (local) connections. A Dense neuron on 28×28 sees 784 inputs. A conv neuron sees 9. Images are locally smooth: an edge is a local event. You should not need every pixel to detect a short line.

Tied weights (sharing). The same 9 weights are used at every location. Equivariance: if you shift the object, the feature map shifts too. A Dense net would have to relearn “edge” in every position separately — a waste of parameters and a worse inductive bias.

Many filters and depth

One kernel = one pattern = one feature map. Conv2D(32) is 32 different kernels, 32 maps stacked as channels. The next convolution looks at a 3×3 patch across all 32 channels at once, so it can combine “vertical edge in this map” with “dark blob in that map.”

Hierarchy: after pooling, each cell sees a larger receptive field of the original image. Layer 1: local edges. Layer 2: corners, loops. Deeper: object parts. Classification then only needs a vector (Flatten or global average pool) and a Dense/softmax head.

Equivariance, then a little invariance

Tied weights give translation equivariance: shift the cat, the feature map shifts. Classification usually wants invariance: the label “cat” should not change if the cat moved. Pooling (and later, seeing the object in many positions during training) is how you go from “the pattern moved” to “it is still a cat.” They are not the same property.

Pooling

Max pooling 2×2 with stride 2: keep the largest value in each 2×2. The map halves. Theory: (1) fewer spatial positions → cheaper Dense tail; (2) a little invariance to tiny shifts (“the edge is somewhere in this 2×2”). Average pooling exists; these notebooks use max. You can also downsample with stride-2 convolution instead of pool; CIFAR’s blocks still pool.

Labs for kernel, size formula, and pooling are in lesson 04. Lesson 03 is the experiment: same digits, MLP vs CNN.

5. Theory after a basic CNN

Once you can classify with conv + pool + Dense, four extra ideas appear. They are not “more Keras verbs.” They are different theories of what the network is for.

Regularization (keep generalization)

Dropout: at train time, randomly zero some neurons. The net cannot rely on one co-adapted clique. At test time all neurons are on (scaled). Augmentation: the true data distribution includes flips and lighting changes; showing warped copies is a prior that “this still has the same label.” Weight decay (AdamW) prefers smaller weights, a smoother function. Early stopping treats “val just got worse” as “stop before memorization.”

Transfer learning (reuse a function you cannot afford to learn)

ImageNet trained a CNN to distinguish 1000 object classes. Early filters (edges, color blobs) transfer to flowers and fundi. Theory: low-level visual statistics are shared; high-level class heads are not. So you freeze the backbone (feature extraction), train a small new head, then optionally fine-tune the last blocks with a tiny learning rate so you do not wash out the pretrained solution (catastrophic forgetting). include_top=False throws away the 1000-way head. Match preprocess_input or the features are in the wrong numeric world. Grad-CAM asks which pixels the classifier used; it is explanation, not a mask you trained.

Embeddings and metric learning (stop using class names)

Softmax assumes a fixed list of classes. People are not a fixed list. An embedding is a vector such that distance ≈ meaning. A Siamese net is two copies of the same DNN with shared weights; contrastive loss pulls same-identity pairs together and pushes others beyond a margin. At test time you only compare distances (cosine if vectors are length 1). Detection (a box) is a different question from recognition (a name).

Pixel-wise prediction (segmentation)

Classification throws away where. To draw a tumor you need an output tensor the same size as the input. A plain CNN encoder shrinks the grid; a decoder must grow it back. Skip connections copy high-resolution encoder maps into the decoder so edges are not invented from a tiny bottleneck. That U-shape is U-Net. Dice is the right objective when positives are rare: accuracy of “all background” is ~99% and useless.

Lesson 01 · Deep_Neural_Network (1).ipynb

A deep neural net before any images

This file is the course’s first DNN: a feedforward stack of Dense layers. It is not computer vision. That is the point. The same theory — layers, activations, loss, backprop — is reused on pixels later. The diabetes table is only the example.

Read Words & theory (section 2–3) first if the words “DNN,” “ReLU,” or “loss vs metric” are still fuzzy. This lesson retells that theory with one concrete architecture.

What a DNN is doing

You have inputs x (here: eight numbers about a person) and a label y (here: diabetes yes/no). You do not write a medical rule. You write a parameterized function ŷ = f(x; weights) and you search for weights that make ŷ close to y on many examples.

Each neuron is the same tiny calculator:

z = w1·x1 + w2·x2 + … + b    then    y = activation(z)

A Dense (fully connected) layer is a bank of such neurons. Every neuron sees every value from the previous layer. That is the MLP inductive bias: any feature may interact with any other. For eight medical numbers that is reasonable. For a 28×28 photo it is wasteful — you would be mixing the top-left pixel with the bottom-right as freely as with its neighbor.

Deep means you stack several of those layers. Layer 1 builds simple mixes of the raw inputs. Layer 2 mixes those mixes. You never name the mixes; training discovers them. Without a nonlinear activation between layers, the stack would collapse to one linear map (see theory: composition of linear maps is linear).

Lab · one neuron

Why these two activations

ReLU on hidden layers

max(0, z). Negatives are silenced; positives pass through. The derivative is 0 or 1, so gradients do not shrink the way they do with sigmoid-in-every-layer (vanishing gradients). Default hidden activation in every notebook here.

Sigmoid on the last layer

One number squeezed into (0, 1): a probability of “yes.” Correct for a binary label. Wrong for 10 exclusive clothing classes — those need softmax, because you need K probabilities that sum to 1, not one independent yes/no.

The last layer is a claim about the kind of answer. Hidden layers are representation; the output layer is the interface to the loss.

What training is (not just the Keras verbs)

Three different numbers get confused in this notebook:

  • Loss (binary crossentropy) — the objective. Training’s only job is to shrink it. It is not a percent.
  • Metric (accuracy) — a report card after thresholding ŷ at 0.5. Adam does not follow accuracy.
  • Prediction — a probability in (0, 1). You still choose a threshold if you need a hard 0/1.

Backpropagation is the chain rule through the stack, so every weight — including the first Dense layer — gets a gradient of that loss. Adam uses those gradients to step. Learning rate is the step size. Batch size is how many rows you average the gradient over before a step (here: 10 — noisy, many updates per epoch). Epoch is one pass over the training rows (here: 100). More epochs are not automatically better; they are more chances to overfit.

The comment “configuring back-propagation” on compile is close: compile binds the loss and optimizer. fit is the loop that actually runs forward → loss → backward → step.

model.compile(
    loss='binary_crossentropy',  # matches sigmoid + yes/no
    optimizer='adam',
    metrics=['accuracy']         # watched, not optimized
)
model.fit(X_train, y_train, epochs=100, batch_size=10)
scores = model.evaluate(X_test, y_test)
model.predict(X_test[11:22])     # probabilities, not 0/1

Their test accuracy was about 71%. That is a DNN on a tiny messy table, not a vision result. The reusable fact is the loop, not the 71%.

Train / test (generalization, not a Keras detail)

Fitting on all 768 rows and then scoring the same rows would measure memorization. train_test_split(..., test_size=0.2) holds out 20% so the score can claim something about generalization. This notebook has no separate validation set. Later MNIST adds validation_split so you can watch overfitting during training and stop. Theory: val is for decisions; test is for one honest number.

Theory the notebook skips (and why it matters)

  • Features are not scaled. Glucose is ~0–200, pedigree is ~0–2. A Dense net with one shared learning rate treats those as different “sizes of knob.” Always scale tables (StandardScaler). Images later use /255 for the same reason: put coordinates on a comparable range.
  • Zeros in Insulin / SkinThickness are often missing values, not true zeros. The model will treat “missing” as a medical fact.
  • No random_state — the split (and therefore the score) changes every run. A theory of generalization needs a fixed test set.
  • Printing loss * 100 looks like a percent. Loss is not a percent.

Lesson 04 · Theory behind the CNN cells

How convolution actually works

The handwritten notebook uses Conv2D and MaxPool without deriving them. This lesson is that derivation, in the same numbers those cells use.

A filter is a tiny shared pattern-detector

A 3×3 kernel (filter) slides over the image. At each stop it multiplies overlapping pixels by its 9 weights and adds them up. That one number goes into a feature map.

Early filters learn edges and textures. Deeper filters learn parts (loops of an 8, petals, an eye). You do not draw the filters. Training writes them.

Two reasons this beats Flatten + Dense:

  • Local connectivity — a neuron only looks at a small neighborhood, which is how images are structured.
  • Weight sharing — the same 3×3 is reused everywhere, so “vertical edge” is detected in every location with the same 9 weights. Far fewer parameters than a Dense layer on 784 pixels.
MLP (Flatten + Dense)CNN
Sees the photo asA bag of 784 numbersA grid; neighbors stay neighbors
ParametersHuge (every pixel to every neuron)Small shared kernels
TranslationA shifted 7 looks like new dataThe same filter still finds the stroke
Your MNIST run~97.5% test~99.1% test

That is the whole “CNN theory”: convolution = sliding shared filters; then pooling shrinks; then maybe Dense at the end for classes. Everything after this lesson (augmentation, transfer, U-Net) still uses this block.

Lab · 5×5 image, 3×3 kernel

Padding and stride

Stride is how many pixels the kernel jumps. Stride 1 = dense scan. Stride 2 = skip every other location, map shrinks faster.

Padding adds extra pixels (usually zeros) around the border so the kernel can sit on edge pixels too. Keras default is valid (no padding). That is why MNIST goes 28 → 26 with a 3×3 filter: 28 − 3 + 1 = 26. same padding keeps 28 → 28 when stride is 1.

Lab · output size

MNIST CNN path, all valid padding, pool stride 2:

28 → conv 26 → pool 13 → conv 11 → pool 5, then 64 maps → 5×5×64 = 1600 numbers into Dense.

Pooling

Max pooling 2×2 with stride 2 keeps the strongest response in each 2×2 block and throws the rest away. Effects: smaller maps (cheaper Dense at the end), a little translation tolerance (“the edge is somewhere in this 2×2”).

Lab · max pool

Many filters = depth

One 3×3 kernel makes one feature map. Conv2D(32, …) is 32 different kernels, so 32 maps stacked as channels. The next conv looks across those 32 channels at once. That is why the second MNIST conv has more parameters: each of 64 new filters sees a 3×3×32 patch.

params = (kernel_h × kernel_w × in_channels × out_channels) + out_channels (bias)

First MNIST conv: (3×3×1×32)+32 = 320. Second: (3×3×32×64)+64 = 18,496.

Receptive field, in one sentence

After two 3×3 convs and two 2×2 pools, each number in the 5×5 map “sees” a much larger patch of the original 28×28 digit. That is how a CNN goes from local edges to a whole handwritten 4.

Lesson 05 · data_augmentation_comparison.ipynb

Teach the model the same object, slightly wrong

CIFAR-10 is 32×32 color photos (airplane, cat, truck, …). The notebook trains the same CNN twice. Only the training transforms change. That isolates what augmentation is worth.

Framework: PyTorch, not Keras. Same ideas: conv blocks, ReLU, pooling, dropout, cross-entropy, Adam-style optimizer.

What augmentation is

You do not invent new labeled photos. You warp the ones you have: flip, crop, jitter color, small rotate. A flipped cat is still a cat. The model sees more variety and memorizes exact pixels less.

Never augment the test (or validation) set if you want an honest score. The notebook’s test loader is normalize-only.

What they applied

TransformWhy it is fair on CIFAR
RandomHorizontalFlipA car facing left is still a car.
RandomCrop(32, padding=4)Classic CIFAR recipe: pad then crop, like a small shift.
ColorJitterLighting changes should not change the class.
Small rotationSlight camera tilt.
Normalize with CIFAR mean/stdNot /255. Dataset-specific centering. Always denormalize before plotting.

Do not blindly flip digits

A horizontal flip of MNIST 2 is still a 2. A 180° rotation can turn 6 into 9. Augmentation must preserve the label. Fashion shirts can flip; medical laterality sometimes cannot.

The CNN (same for both runs)

Three conv blocks (two 3×3 conv+BatchNorm+ReLU, then max pool), then global average pool, Dense 512, Dropout 0.3, 10 logits. Loss is CrossEntropyLoss on integer labels — PyTorch applies log-softmax inside the loss, so the last layer is not softmax.

Optimizer: AdamW, cosine annealing over 30 epochs. That slowly lowers the learning rate. Different stack, same training story as Keras fit.

How to read the experiment

  • The augmented model’s train accuracy rises slower (training is harder).
  • Its test accuracy ends higher.
  • The gap train_acc − test_acc shrinks. That gap is a simple overfitting score.

Keras version of the same idea: the flowers notebook’s ImageDataGenerator (flip, rotation 20°, shift, zoom, shear, brightness) applied to train only.

Lesson 06 · transfer_learning_tf.ipynb

Borrow a brain that already saw a million photos

You have ~4,300 flower photos and five classes. Training a huge CNN from random weights will overfit. ImageNet already taught MobileNetV2 edges, textures, and object parts. You reuse that.

transfer_learning_tfh.ipynb is the same file. It does not use TF Hub. Dataset: Kaggle alxmamaev/flowers-recognition — daisy, dandelion, rose, sunflower, tulip. Split 70 / 15 / 15.

Transfer learning in two phases

Phase 1 · feature extraction

Freeze the MobileNetV2 backbone. Train only a small new head. Fast. Safe. Learning rate ~1e-3.

Phase 2 · fine-tuning

Unfreeze the last 30 backbone layers. Train them + the head with a tiny LR (~1e-5) so you do not erase ImageNet features (catastrophic forgetting).

include_top=False throws away ImageNet’s 1000-class classifier. You keep the visual trunk and attach your 5-class head.

Input 224×224×3
↓ MobileNetV2 ImageNet weights, include_top=False
GlobalAveragePooling2D → BatchNorm → Dense 256 → Dropout 0.3 → Dense 128 → Dropout 0.2
↓
Dense 5, softmax

Global Average Pooling turns a stack of feature maps into one number per channel. No giant Flatten. Fewer parameters, harder to overfit.

The preprocess trap

MobileNetV2 expects preprocess_input, which scales roughly to [−1, 1]. Using /255 from the MNIST notebooks here will look like it “runs” and still be wrong. Val/test generators use preprocess only — no augmentation.

Call the backbone with training=False so BatchNorm keeps its ImageNet running statistics. If those stats update on a small flower set, the features can collapse. Official TensorFlow transfer-learning guidance is exactly this.

Callbacks — stop being a hero

CallbackJob
EarlyStopping (restore_best_weights)Quit when val stops improving; snap back to the best epoch, not the last.
ReduceLROnPlateauIf val stalls, cut LR in half.
ModelCheckpointSave the best weights to disk.
TensorBoard / CSVLoggerLook at curves later.

Recompile before Phase 2. A fresh Adam at 1e-5 should not carry Phase-1 momentum into the unfrozen layers.

Grad-CAM

After training, you want to know where the model looked. Grad-CAM takes the gradient of the predicted class score with respect to the last convolutional feature map and paints a heatmap. For flowers, the blob should sit on the bloom, not the table. For eyes (next medical lesson), it should sit on lesions, not the black border.

Evaluate like an adult

Accuracy on five fairly even flower classes is OK as a headline. Still plot a confusion matrix and per-class F1. shuffle=False on the test generator so predictions line up with labels.

Their ballpark: after fine-tune, val ~88–92%, test ~88–91%. Far above what a tiny from-scratch CNN would do on 4k photos.

Lesson 08 · siamese_network_tutorial.ipynb

Stop naming people. Learn a distance.

Softmax over 40 identities fails as soon as person 41 walks in. A Siamese net does not output “Alice / Bob”. It outputs how far two face embeddings are. New people only need a reference photo.

AT&T / ORL: 40 people × 10 photos, grayscale .pgm 92×112. Pairs: 20 same + 20 different per person (label 0 = same, 1 = different).

Shared weights

Two input photos go through the same CNN encoder. Same weights. If the towers differed, “distance” would be meaningless. The encoder ends in a 128-D vector, L2-normalized (length 1), so Euclidean distance behaves like an angle on a sphere.

Image A 112×92×1    Image B 112×92×1
↓ same encoder (4 conv blocks → GAP → Dense 128 → L2)
embedding A    embedding B
↓ Euclidean distance
one number d · contrastive loss

Contrastive loss (Hadsell-style)

This notebook uses y = 0 for the same person and y = 1 for different people. Many tutorials flip that. Copy the formula that matches your labels.

L = ½ [ (1−y) d² + y max(0, margin − d)² ]    with margin = 1.0
  • Same pair (y=0): loss is ½ d². Pull embeddings together.
  • Different pair (y=1): if d already > margin, loss is 0. Otherwise push them apart. No need to send strangers to infinity.

Lab · contrastive loss

Verification vs identification vs one-shot

  • Verification: two photos, same person? Threshold on d (they sweep 0–2 on test; slightly optimistic — prefer tuning on val).
  • Identification: one query vs a gallery, nearest embedding wins.
  • One-shot: gallery has one photo per person. Softmax classifiers cannot do this without retraining.

They also plot t-SNE (pretty 2D view of clusters — not a metric) and ROC-AUC on pair distances.

Optimistic splits

Pair-level train/test still lets the same person appear on both sides. For a true one-shot test you hold out subjects, not just pairs. Tiny 400-image sets also memorize easily without augmentation.

Lesson 09 · Face_Recognition_Based_Attendance.ipynb

You often do not train. You engineer a pipeline.

Siamese taught the idea of embeddings. This notebook downloads a stronger pretrained one (ArcFace) and a face detector, then logs names to CSV. Production CV is frequently this: glue, thresholds, and a UI.

Detection is not recognition

  1. Detect — OpenCV Res10 SSD (300×300) finds a box. Confidence default 0.80, min face 80 px, keep the largest face.
  2. Crop — pad 8% so you do not cut ears/chin, resize to 112×112 RGB.
  3. Embed — ArcFace ONNX, preprocess (x − 127.5) / 128, output 512-D, L2-normalize.
  4. Match — cosine distance to enrolled gallery. Accept if distance < 0.40.
  5. Log — one attendance row per person per day.

Enrollment photos live in known_Faces/ with names like 1234_JohnDoe.jpg. Extra underscores in the name will split wrong — the notebook documents that quirk.

Cosine on the unit sphere

After L2-normalization, cosine similarity is just the dot product. Distance = 1 − similarity. Lower threshold = stricter (fewer false accepts, more “unknown”).

Lab · cosine match

Why ONNX

ONNX Runtime runs a trained model without bringing PyTorch or TensorFlow into the attendance app. Layout matters: this ArcFace is NHWC (1, 112, 112, 3). Many face models are NCHW. Wrong layout → garbage embeddings that still look like 512 numbers.

Limits you should say out loud

  • No liveness check — a printed photo can pass.
  • SSD is old; profile, mask, hard light will miss faces.
  • Threshold 0.40 is a default, not calibrated FAR/FRR on your camera.
  • Face embeddings are biometric data. You need consent and a retention policy. This is a class demo, not a workplace system.

U-Net: down, then up, with shortcuts

A classification CNN shrinks the grid until a vector remains. That throws away where. U-Net (Ronneberger, 2015, biomedical) keeps where:

  1. Encoder — conv + pool. “What is this?” Maps get smaller, channels grow.
  2. Bottleneck — the bottom of the U.
  3. Decoder — upsample back to full size so every pixel can get a label.
  4. Skip connections — copy encoder maps across and concatenate them. The decoder sees both deep context and sharp edges.

Sequential cannot do skips. Same Functional API idea as the Siamese net, different graph.

Input 128×128×1
↓ Conv 16, 16 · pool → 64×64
c1 saved for a skip
↓ Conv 32, 32 · pool → 32×32
c2 saved for a skip
↓ Conv 64 (bottleneck)
UpSample · concat c2 · Conv 32
↓
UpSample · concat c1 · Conv 16
↓ Conv2D(1, 1×1, sigmoid)
Per-pixel P(tumor), then threshold 0.5

This is a mini U-Net: two down-levels, 16→32→64 channels, UpSampling2D instead of learned Conv2DTranspose, padding='same' so concat sizes match. The paper U-Net is deeper. The idea is the same.

Dice, not accuracy

Dice = 2 × |true ∩ pred| / (|true| + |pred|)    ·    dice_loss = 1 − Dice

Tumors are tiny. A model that paints every pixel black can be ~99% accurate and still miss the tumor. Dice only scores overlap of the white blob. IoU (intersection over union) is the harsher cousin; this notebook does not log it.

Lab · Dice vs accuracy

def dice_loss(y_true, y_pred):
    smooth = 1.
    y_true_f = tf.reshape(y_true, [-1])
    y_pred_f = tf.reshape(y_pred, [-1])
    intersection = tf.reduce_sum(y_true_f * y_pred_f)
    return 1 - (2. * intersection + smooth) / (
        tf.reduce_sum(y_true_f) + tf.reduce_sum(y_pred_f) + smooth)

model.compile(optimizer="adam", loss=dice_loss, metrics=["accuracy"])
model.fit(X_train, y_train, epochs=20, batch_size=8, validation_split=0.1)

Checklist (print this next to Colab)

  2. Fix labels (typos, missing values, ordinal vs nominal).
  3. Split so test never leaked. Stratify if classes are uneven.
